# M2: Build Pipeline, English Fonts, VWF — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command (`python lm.py build`) produces a patched, expanded ROM with original English fonts and a variable-width-font (VWF) dialogue renderer, plus a `.bps`. English test lines render correctly in the field, battle, item and personal-info windows.

**Architecture:**
- **Build** (`lmtools/build.py`): base ROM → `expand` → asar (`src/asm/main.asm`) → write font data → insert script (EN with JP fallback, layout read from the base ROM) → checksum → `build/lm_en.sfc` + flips `.bps`.
- **Fonts:**
  - Both come from hand-drawn ASCII-art sources (`src/font/*.txt`) via `lmtools/font.py`.
  - Fixed 8x16 English glyphs replace single-byte tiles `$20-$7E` in the original font (PC `170000`), for paths that draw tile = char code.
  - VWF glyphs and widths go to the expanded bank `$C0`.
- **VWF:** a draw-time hook in the renderer (`$00:BE70`). It ORs each glyph into per-line tile cells in the existing dynamic-tile buffer `$7F:B000`: 4 line slots x 32 cells = 128 tiles = VRAM tiles `$180-$1FF`. It then requests the NMI upload (`$57=$FE`, `$78=$6C00`).

**Tech Stack:** Python 3.12 + pytest + Pillow, asar (65816 assembler), flips (BPS), Mesen2 headless (Lua).

**Spec:** `docs/superpowers/specs/2026-10-05-little-master-translation-design.md`. M1 facts: `docs/re/README.md` → "Facts M2 needs", plus `docs/re/text-engine.md`.

## Facts this plan relies on (from M1 + pre-plan spike, 2026-10-06)

- **Renderer** (`$00:BE4F` loop, 16-bit A/X, X = tilemap byte offset):
  - Single-byte char path: `$BE70 CMP #$00CE / BEQ $BE4F`, then `$BE75 JSR $C156`.
  - `$BE78`: `INC $0A10`, delay `JSR $C1B4` when `$0A0A` != 0.
  - `$BE88`: if `$0A06` == 0, then `INX INX / INC $09FC`.
  - `$BE92`: wrap check `$09FC-1 >= $09F8`.
- **Character cell:** a single-byte char is ONE 2bpp tile.
  - Top 8 rows in bitplane 0, bottom 8 rows in bitplane 1.
  - Tilemap `$7E:9000+X = tile + $0A02` and `$7E:9040+X = tile + $0A02 + $0400` (the palette+1 entry shows the other plane).
  - Tile byte `2r` = top row r, byte `2r+1` = bottom row r (row r+8).
- **Dynamic tiles:** `$7F:B000` (`$800` bytes = 128 tiles) is uploaded by the NMI to VRAM word `$6C00` (= text BG tiles `$180-$1FF`) after `$78=#$6C00` and `$57=#$FE` (8-bit). `$00:E3BE` waits for the NMI. The kanji preprocessor fills this buffer only when kanji slots `$0A18` > 0.
- **Window RAM:** `$09F0/$09F2` origin, `$09F8` wrap column, `$09FC/$09FE` cursor col/row, `$0A02` attribute, `$0A0A` speed, `$0A1C` alt mode (menus: VRAM `$4800`, tile*2).
- **Measured windows** (`test/states/*.mss`):

  | State | Window | `$0A1C` |
  |---|---|---|
  | `ordinary_field_message` | 28 cols x 2 lines | 0 |
  | `batte_message` / `batte_caution` | 28 x 3 | 0 |
  | `item_menu` | col 11, 19 x 3 | 0 |
  | `personal_infomation`, `report` | 29 x 3 | 0 |

- **Free RAM:** `$7F:FF00-$7F:FFFF` was neither read nor written in a 3600-frame run (re-verified in Task 4).
- **Newline handler** `$00:BF01` starts `LDA $09FE (AD FE 09) / CMP #$003E`.
- **Window clear** `$01:ECE5` starts `REP #$20 (C2 20) / LDA #$2000 (A9 00 20)`.
- **Cursor set** `{pXX:YY}`: `$00:BF8E AND #$001F / $BF91 STA $09FC (8D FC 09) / $BF94 LDA [$14] (A7 14)`.

## Review Focus

1. **Hand-edited EN line with characters outside `en.tbl`** (`[`, `{`, kana) → the build fails naming block, #id and character; no partial ROM is written. (Task 2 test.)
2. **Missing tool** (asar/flips not in `tools/`) → a clear error naming the expected path, not a `FileNotFoundError` traceback. (Task 1 test.)
3. **Partially translated script** (EN empty) → JP fallback, so the build still round-trips those strings. (Task 1 test.)
4. **Glyph wider than 8 px, or an art row of the wrong length** → the font converter raises with the char and line. (Task 3 test.)
5. **A message with more line segments than 4 slots**, or a fixed-mode window (`$0A1C` != 0) → VWF falls back to the fixed font instead of corrupting tiles. (Task 6 Lua check.)

```python
"""Build: base -> expand -> asar -> fonts -> script -> checksum -> .sfc + .bps."""
import subprocess
from pathlib import Path

from . import rom
from .blocks import insert_block, load_blocks
from .script import parse
from .tbl import Table

ROOT = Path(__file__).resolve().parent.parent
ASAR = ROOT / "tools" / "asar" / "asar.exe"
FLIPS = ROOT / "tools" / "flips" / "flips.exe"
MAIN_ASM = ROOT / "src" / "asm" / "main.asm"


def _tool(path, name):
    if not path.exists():
        raise FileNotFoundError(f"{name} not found at {path} (download it into tools/{name}/)")
    return str(path)


def build(out_dir="build", source="en") -> Path:
    out_dir = Path(out_dir)
    out_dir.mkdir(parents=True, exist_ok=True)
    asar, flips = _tool(ASAR, "asar"), _tool(FLIPS, "flips")
    base = rom.load_base()
    work = rom.expand(bytearray(base))
    sfc = out_dir / "lm_en.sfc"
    sfc.write_bytes(work)
    r = subprocess.run([asar, "--no-title-check", "--fix-checksum=off", str(MAIN_ASM), str(sfc)],
                       capture_output=True, text=True)
    if r.returncode:
        raise RuntimeError(f"asar failed:\n{r.stdout}{r.stderr}")
    work = bytearray(sfc.read_bytes())
    jp, en = Table.load(ROOT / "tbl/jp.tbl"), Table.load(ROOT / "tbl/en.tbl")
    padded_base = rom.expand(bytearray(base))
    for b in load_blocks(ROOT / "data/blocks.json"):
        entries = parse((ROOT / f"script/{b.name}.txt").read_text(encoding="utf-8"))
        insert_block(work, b, entries, jp, source, en_tbl=en, base=padded_base)
    rom.fix_checksum(work)
    sfc.write_bytes(work)
    clean = out_dir / "_clean.sfc"
    clean.write_bytes(rom.load_base())
    r = subprocess.run([flips, "--create", "--bps", str(clean), str(sfc), str(out_dir / "lm_en.bps")],
                       capture_output=True, text=True)
    clean.unlink()
    if r.returncode:
        raise RuntimeError(f"flips failed:\n{r.stdout}{r.stderr}")
    return sfc
```

### Task 3: Font sources + converter

**Files:** Create `lmtools/font.py`, `tests/test_font.py`, `src/font/vwf.txt`, `src/font/fixed.txt`; modify `lmtools/build.py`.

**Font source format** (both files):
```
; comment (a line starting with ';')
char A
.......
..##...
...      (exactly 16 rows; '#' = ink, '.' = paper; row length = advance width incl. 1 px spacing, 1..8)
char space
....
...
```
- `char X`: the literal character X.
- `char space`: the space character.
- Rows 0-15 top to bottom.
- Fixed font: every glyph exactly 8 wide.
- Baseline conventions: cap height rows 2-12, x-height rows 5-12, descenders to row 14, row 15 empty. This matches the 16 px kanji line.

**Interfaces:**
- `parse_font(text: str) -> dict[str, tuple[int, list[int]]]`: char → (width, 16 row bytes, MSB = leftmost).
- `vwf_blobs(font) -> tuple[bytes, bytes]`: glyphs (95 x 16 bytes for `$20-$7E`, zeros for missing), widths (95 bytes).
- `fixed_tiles(font) -> bytes`: 95 x 16 bytes of 2bpp tiles. Byte `2r` = row r, byte `2r+1` = row r+8.

- [ ] **Step 2: Implement** `lmtools/font.py`:

```python
"""ASCII-art font sources -> VWF glyph/width blobs and fixed 2bpp (plane0 = top, plane1 = bottom) tiles."""


def parse_font(text):
    font, name, rows = {}, None, []

    def close():
        if name is None:
            return
        if len(rows) != 16:
            raise ValueError(f"char {name}: needs 16 rows, got {len(rows)}")
        w = len(rows[0])
        if not 1 <= w <= 8 or any(len(r) != w for r in rows):
            raise ValueError(f"char {name}: width must be 1-8 and equal on every row")
        font[" " if name == "space" else name] = (w, [int(r.replace("#", "1").replace(".", "0").ljust(8, "0"), 2)
                                                       for r in rows])

    for line in text.splitlines():
        if not line.strip() or line.startswith(";"):
            continue
        if line.startswith("char "):
            close()
            name, rows = line[5:], []
        else:
            rows.append(line.strip())
    close()
    return font


def vwf_blobs(font):
    glyphs, widths = bytearray(95 * 16), bytearray(95)
    for ch, (w, rows) in font.items():
        i = ord(ch) - 0x20
        glyphs[i * 16:i * 16 + 16] = bytes(rows)
        widths[i] = w
    return bytes(glyphs), bytes(widths)


def fixed_tiles(font):
    out = bytearray(95 * 16)
    for ch, (_, rows) in font.items():
        i = (ord(ch) - 0x20) * 16
        for r in range(8):
            out[i + 2 * r], out[i + 2 * r + 1] = rows[r], rows[r + 8]
    return bytes(out)
```

### Task 5: VWF assembly

**Files:** Create `src/asm/vwf.asm`; modify `src/asm/main.asm` (`incsrc "vwf.asm"`).

**Design** (per character, renderer context, 16-bit A/X, DB = `$00`):
- **Line slots:** line slot `L` (0-3) at `!line`, pixel offset `px` (0-7) at `!px`. The cell for cursor column `c = $09FC & 31` uses tile `T = $180 + L*32 + c`, which lives at `$7F:B000 + (L*32 + c)*16`.
- **Draw glyph g** (width w): for rows r = 0-15, `v = glyph[r] << 8 >> px` (16-bit). The high byte is ORed into tile T at row r; the low byte into tile T+1 (`c < 31`). Row r goes to byte `2r` when r < 8, else to byte `2(r-8)+1`. Write tilemap entries for cell c (and for c+1 if `px+w > 8`) exactly like `$C156`'s plain path.
- **Advance:** `px += w`. While `px >= 8`: `px -= 8`, `X += 2`, `$09FC += 1`. Then pre-decrement (`X -= 2`, `$09FC -= 1`) and `JML $00BE78`, so the game's own `INX INX / INC $09FC` at `$BE88` restores the right position. The delay, upload and wrap logic stay native.
- **Upload request:** after each glyph, `$78 = #$6C00`, `$57 = #$FE` (8-bit store).
- **Newline** (`$BF01` hook): `px = 0`, `L = (L+1) & 3`, zero the 32 tiles of slot L (512 bytes), then replay `LDA $09FE` and `JML $00BF04`.
- **Window clear** (`$01:ECE5` hook): `px = 0`, `L = 0`, zero all 128 tiles **only if `$0A18` == 0** (no kanji in this message), then replay `REP #$20 : LDA #$2000` and `JML $01ECEA`.
- **Cursor set** (`$BF91` hook): replay `STA $09FC`, then `px = 0`, `L = (L+1) & 3`, clear slot L, then `LDA [$14]` and `JML $00BF96`.
- **Fallback to fixed font:** any of the following leaves the original path untouched (`CMP #$00CE / BEQ`, then `JML $00BE75`), so menus and JP text keep working.
  - `$0A1C` != 0;
  - `$0A18` != 0 (a message with kanji, i.e. JP fallback);
  - char outside `$20-$7E`.

- [ ] **Step 1: Write `src/asm/vwf.asm`**

```asm
; VWF for the dialogue renderer. See docs/re/text-engine.md "Dynamic tiles and VWF hooks".
; All VWF RAM is long-addressed (.l) because DB belongs to the game.
!px    = $7FFF00          ; pixel offset in current cell (0-7)
!line  = $7FFF02          ; line slot 0-3
!gptr  = $7FFF04          ; glyph pointer inside bank $C0
!toff  = $7FFF06          ; byte offset of tile T inside !slots
!row   = $7FFF08          ; glyph row 0-15
!wid   = $7FFF0A          ; glyph advance width
!v     = $7FFF0C          ; row << 8 >> px (16-bit)
!tile  = $7FFF0E          ; tile number of the current cell
!slots = $7FB000          ; 128 x 16-byte 2bpp tiles -> VRAM tiles $180-$1FF

org $00BE70               ; was: CMP #$00CE / BEQ $BE4F
    JML vwf_dispatch
    NOP

org $00BF01               ; was: LDA $09FE / CMP #$003E (first byte)
    JML vwf_newline

org $00BF91               ; was: STA $09FC / LDA [$14]
    JML vwf_setcol
    NOP

org $01ECE5               ; was: REP #$20 / LDA #$2000
    JML vwf_clear
    NOP

org $C08000
vwf_glyphs:   skip $600   ; filled by build: 95 x 16 bytes, chars $20-$7E
vwf_widths:   skip $60    ; filled by build: 95 bytes (PC 200600 = $C0:8600)
assert vwf_widths == $C08600

vwf_dispatch:             ; renderer context: A = char (16-bit), X = tilemap offset (16-bit)
    CMP #$00CE : BNE + : JML $00BE4F
+   PHA
    LDA $0A1C : ORA $0A18 : BNE .fixed          ; menu mode or kanji present -> original renderer
    LDA 1,s : CMP #$0020 : BCC .fixed : CMP #$007F : BCS .fixed
    PLA
    JSR vwf_draw
    DEX : DEX : DEC $09FC                       ; pre-decrement: native $BE88 adds one cell back
    JML $00BE78
.fixed:
    PLA
    JML $00BE75                                 ; JSR $C156 (fixed glyph = tile code)

vwf_draw:                 ; A = char, X = tilemap offset; updates X/$09FC/!px
    SEC : SBC #$0020 : STA.l !gptr               ; glyph index
    PHX
    TAX
    SEP #$20 : LDA.l vwf_widths,x : REP #$20 : AND #$00FF : STA.l !wid
    LDA.l !gptr : ASL : ASL : ASL : ASL : CLC : ADC #vwf_glyphs&$FFFF : STA.l !gptr
    LDA.l !line : ASL : ASL : ASL : ASL : ASL : STA.l !toff       ; line*32
    LDA $09FC : AND #$001F : CLC : ADC.l !toff
    ASL : ASL : ASL : ASL : STA.l !toff                            ; (line*32 + col) * 16
    LDA #$0000 : STA.l !row
.row:
    LDA.l !gptr : CLC : ADC.l !row : TAX
    SEP #$20 : LDA.l $C00000,x : REP #$20        ; glyph row byte from bank $C0
    AND #$00FF : XBA : STA.l !v                  ; row << 8
    LDA.l !px : TAX
-   CPX #$0000 : BEQ +
    LDA.l !v : LSR : STA.l !v : DEX : BRA -
+   LDA.l !row : CMP #$0008 : BCC +
    SEC : SBC #$0008 : ASL : INC : BRA ++        ; bottom half: byte 2(r-8)+1
+   ASL                                          ; top half: byte 2r
++  CLC : ADC.l !toff : TAX
    SEP #$20
    LDA.l !v+1 : ORA.l !slots,x : STA.l !slots,x          ; high byte -> tile T
    LDA.l !v : ORA.l !slots+16,x : STA.l !slots+16,x      ; low byte  -> tile T+1
    REP #$20
    LDA.l !row : INC : STA.l !row : CMP #$0010 : BCC .row
    PLX
    LDA.l !toff : LSR : LSR : LSR : LSR : CLC : ADC #$0180 : STA.l !tile
    CLC : ADC $0A02 : STA.l $7E9000,x : CLC : ADC #$0400 : STA.l $7E9040,x
    LDA.l !px : CLC : ADC.l !wid : STA.l !px
.adv:
    LDA.l !px : CMP #$0008 : BCC .done
    SEC : SBC #$0008 : STA.l !px
    INX : INX : INC $09FC
    LDA.l !tile : INC : STA.l !tile
    CLC : ADC $0A02 : STA.l $7E9000,x : CLC : ADC #$0400 : STA.l $7E9040,x
    BRA .adv
.done:
    LDA #$6C00 : STA $78                          ; NMI uploads !slots to VRAM $6C00
    SEP #$20 : LDA #$FE : STA $57 : REP #$20
    RTS

vwf_clearslot:            ; 16-bit A/X/Y: zero the 32 tiles (512 bytes) of slot !line
    LDA.l !line : XBA : ASL : TAX                 ; line * 512
    LDY #$0100
    LDA #$0000
-   STA.l !slots,x : INX : INX : DEY : BNE -
    RTS

vwf_nextline:             ; px = 0, line = (line+1) & 3, clear that slot
    PHP : REP #$30 : PHX : PHY
    LDA #$0000 : STA.l !px
    LDA.l !line : INC : AND #$0003 : STA.l !line
    JSR vwf_clearslot
    PLY : PLX : PLP
    RTS

vwf_newline:
    JSR vwf_nextline
    LDA $09FE
    JML $00BF04

vwf_setcol:
    STA $09FC
    JSR vwf_nextline
    LDA [$14]
    JML $00BF96

vwf_clear:
    PHP : REP #$30 : PHX
    LDA #$0000 : STA.l !px : STA.l !line
    LDA $0A18 : BNE +                             ; kanji in this message: their tiles live in !slots
    LDA #$0000 : LDX #$0000
-   STA.l !slots,x : INX : INX : CPX #$0800 : BNE -
+   PLX : PLP
    REP #$20
    LDA #$2000
    JML $01ECEA
```

Then add `incsrc "vwf.asm"` to `main.asm`.

- **(b)** The glyph read `LDA.l $C00000,x` uses X = `$8000 + idx*16 + row`, which is inside bank `$C0`.
- **(c)** The renderer hooks (`$BE70`, `$BF01`, `$BF91`) run with 16-bit A/X: the surrounding code uses 16-bit immediates. `vwf_clear` and `vwf_nextline` guard the register width with `PHP/REP #$30/PLP`.
- **(d)** Each hook replays exactly the instructions it overwrote before jumping back.
- **(e)** The cell at column 31 spills into the next slot's first tile. Windows are at most 30 columns wide, so this is harmless; document it.
