# M6 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.0: fix the bugs from the user's playthrough, then produce a `.bps` patch and a readme that states the base ROM checksum.

**Architecture:**
- `lm.py release` builds, verifies the patch against the checked base ROM, and writes `dist/` (the patch, `README.txt`, and a zip).
- `lm.py test` is the spec's single release gate: build, round-trip, lint, pytest.
- The playthrough is a loop. The user reports bugs in `docs/playtest.md`. Each bug gets a failing test (lint rule or Mesen runtime check), then a fix and a commit. A release candidate (RC) goes to the user after each batch.

**Tech Stack:** Python 3.12 (`lmtools/`, `lm.py`, pytest), Mesen2 2.1.1 headless, asar 1.91, our `lmtools/bps.py` (cross-checked with python-bps-continued).

**Spec:** `docs/superpowers/specs/2026-10-05-little-master-translation-design.md`. M6 is: "user playthrough bugs fixed; `.bps` + readme (with base ROM checksum)". Testing: "`python lm.py test` checks that the build succeeds; the round-trip test still passes; the lint and overflow checks pass; the Mesen2 Lua scenario runs pass."

## Global Constraints

- The base ROM is never modified. The patch targets the **unheadered** Japan ROM:
  - 2,097,152 bytes;
  - CRC32 `B916334C`;
  - MD5 `74b01cb4ec81821ee254d2f2e9025d47`;
  - SHA1 `75b76715d4a20371e0340dbeee3a51ff6a1dbad3` (`lmtools.rom.SHA1`).
- No Beta2 code, assets or text are copied.
- `dist/` is gitignored. Release files are build products.
- `python lm.py lint` stays clean, and `python -m pytest -q` stays green after every task.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work happens on branch `m6-work`. Tag `v1.0` only after the user approves the merge.

## Review Focus

1. **A user patches a headered (`.smc`, +512 bytes) or wrong-version ROM.** The readme must say how to check and fix this, and `release` must refuse to build from a wrong base. Test: Task 1 `test_release_refuses_wrong_base`, and the readme text check.
2. **The `.bps` in `dist/` doesn't match the tested build** (stale file, rebuilt after the test). `release` must apply its own patch to the base and compare it with the ROM it just tested. Test: Task 1 `test_release_patch_reproduces_build`.
3. **The readme checksums differ from the real files.** They are computed, never typed by hand. Test: Task 1 `test_readme_checksums_match_files`.
4. **A fix to one script line breaks another screen** (shared strings, window widths). Every fix runs the whole `lm.py test` gate, not just its own test. Test: Task 4 step 4.
5. **A bug the user hits that's lost between sessions.** `docs/playtest.md` is the single log, and a bug is closed only with a test name and a commit. Test: Task 3's ledger check (`test_playtest_closed_bugs_name_tests`).

### Task 1: Release packaging

**Files:** Create `lmtools/release.py`, `src/release/README.txt` and `tests/test_release.py`. Modify `lm.py` and `.gitignore`.

**Interfaces (produces):**
- `release.hashes(data: bytes) -> dict` with keys `size`, `crc32` (8 upper-case hex), `md5` and `sha1`.
- `release.readme(version: str, base: bytes, patched: bytes) -> str`.
- `release.release(version: str, out="dist", build_dir="build") -> Path`. It returns the zip path and writes:
  - `dist/LittleMaster_EN_v<version>.bps`;
  - `dist/README.txt`;
  - `dist/LittleMaster_EN_v<version>.zip` (patch + readme).

  Steps: `rom.load_base()` (raises on a wrong ROM), `build.build(build_dir)`, `bps.apply(base, patch) == built`, then write.
- CLI: `python lm.py release --version 1.0`.

```python
import zipfile
from pathlib import Path

import pytest
from lmtools import bps, release, rom


def test_hashes_known_value():
    h = release.hashes(b"abc")
    assert h == {"size": 3, "crc32": "352441C2", "md5": "900150983cd24fb0d6963f7d28e17f72",
                 "sha1": "a9993e364706816aba3e25717850c26c9cd0d89d"}


def test_readme_checksums_match_files():
    base, patched = bytes(rom.load_base()), b"\x01" * 16
    text = release.readme("1.0", base, patched)
    for v in release.hashes(base).values():
        assert str(v) in text
    assert release.hashes(patched)["crc32"] in text
    assert "512-byte header" in text and "v1.0" in text and "{" not in text


def test_release_patch_reproduces_build(tmp_path):
    z = release.release("0.9", out=tmp_path / "dist", build_dir=tmp_path / "b")
    names = zipfile.ZipFile(z).namelist()
    assert names == ["LittleMaster_EN_v0.9.bps", "README.txt"]
    patch = (tmp_path / "dist" / "LittleMaster_EN_v0.9.bps").read_bytes()
    assert bps.apply(bytes(rom.load_base()), patch) == (tmp_path / "b" / "lm_en.sfc").read_bytes()


def test_release_refuses_wrong_base(tmp_path, monkeypatch):
    bad = tmp_path / "bad.sfc"; bad.write_bytes(b"\0" * 0x200000)
    monkeypatch.setattr(rom, "BASE", bad)
    with pytest.raises(ValueError, match="SHA1"):
        release.release("0.9", out=tmp_path / "dist", build_dir=tmp_path / "b")
    assert not (tmp_path / "dist").exists()
```

```python
import re
from pathlib import Path

def rows():
    text = Path("docs/playtest.md").read_text(encoding="utf-8")
    log = text.split("## Bug log", 1)[1].split("\n## ", 1)[0]
    return [[c.strip() for c in l.strip().strip("|").split("|")] for l in log.splitlines()
            if l.startswith("|") and not set(l) <= set("|- ") and "status" not in l]

def test_playtest_closed_bugs_name_tests():
    rs = rows()
    assert rs, "bug log has no rows"
    for r in rs:
        assert len(r) == 7, r
        assert r[4] in ("open", "fixed", "wontfix"), r
        if r[4] == "fixed":
            assert r[5].startswith("test_") and re.fullmatch(r"[0-9a-f]{7,}", r[6]), r
        if r[4] == "wontfix":
            assert r[5], f"wontfix needs a reason in the test column: {r}"
```

### Task 4: Fix loop (repeat per batch of reports, carry-over first)

For each `open` row, in this order: C1-C3 (engine), then user bugs by severity (crash/softlock > unreadable/overflow > wrong text > polish), then C4:

- [ ] **Step 1: Reproduce with a failing test**
  - **Text that overflows or is wrong:** a lint test (`tests/test_lint.py` style). The case is the entry's `{id}` plus the EN line from the report, asserting the lint message.
  - **Rendering or engine:** a Mesen runtime test in `tests/test_vwf_runtime.py` style. Load the reported `test/states/<state>.mss`, drive the reported inputs, and assert on VRAM, WRAM or the screenshot region. Use the JP-keyed `checked_build` helper so the target string really is the one under test.
  - **Wording only (C4, translation polish):** no new test. Edit the line with `lm.py show`/`lm.py apply`. The test column gets `test_lint_all_clean` (the whole-script gate).
- [ ] **Step 2:** Run it. It must FAIL for the reported reason.
- [ ] **Step 3:** Fix: the script line, `glossary.md` (fix every occurrence, per the spec's "tone fixes are applied across the whole script"), `data/windows.json`, or `src/asm/vwf.asm`.
- [ ] **Step 4:** `python lm.py test` shows 4 PASS lines. Update the bug's log row to `fixed | <test name> | <commit>`, and commit the fix plus the row together.
- [ ] **Step 5:** If a fix is out of scope or not worth the risk (for example, C3 if the slot logic is stable in play), set `wontfix` with the reason, and add a ruling in the ledger.
